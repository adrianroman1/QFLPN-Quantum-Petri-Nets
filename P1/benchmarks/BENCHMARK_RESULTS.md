## 2. Implementations

1. Production: `P1.code.qflpn_transition_operator.qflpn_transition_operator`
2. Independent: `P1.tests.independent_reference.independent_global_operator`

Both implementations construct the same canonical global operator.
Numerical equivalence is checked before timing measurements.

## 4. Relative execution time

**Speedup ratio: NOT AVAILABLE**

The ratio will be calculated as:

independent median execution time / production median execution time

A value greater than 1 means that the production implementation had a
lower median execution time in the measured run. A value below 1 means
that the independent implementation had a lower median execution time.

## 5. Numerical equivalence

**Status: NOT RUN**

The benchmark runner checks the Frobenius norm of the difference between
the two constructed operators against the tolerance 1e-12.

## 6. Reproducibility

The following files are generated by the benchmark runner:

- `benchmark_results.csv` — individual raw timing samples
- `benchmark_report.json` — structured benchmark results
- `environment.txt` — captured execution environment

## 7. Limitations

This benchmark measures only the canonical four-qubit P1 instance
(D = 16). It does not establish asymptotic complexity, large-register
scalability, million-qubit performance, distributed execution, or
HPC speedup.

Timing results are specific to the captured hardware and software
environment. They must not be generalized beyond the measured workload.

## 8. Execution

From the repository root:

```bash
python P1/benchmarks/benchmark_runner.py
```

Optional parameters:

```bash
python P1/benchmarks/benchmark_runner.py --warmups 10 --repetitions 100
```
