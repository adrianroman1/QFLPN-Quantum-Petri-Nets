# P3 — Benchmark Results

## 1. Scope

This document records the measured performance of the P3
Compressed Sparse Row (CSR) sparse matrix-vector multiplication
implementation.

The benchmark measures:

- sequential CSR SpMV;
- parallel CSR SpMV using Java Fork/Join;
- sequential and parallel execution times;
- speedup;
- execution-time reduction;
- numerical consistency;
- benchmark configuration and execution environment.

The benchmark results must be generated by an actual execution
of `hpc.csr.BenchmarkRunner`.

No performance values are inferred from unit tests or CI test
execution times.

## 2. Important distinction: correctness matrix vs benchmark matrix

Two different matrices are used in P3 validation.

### 2.1 Manuscript correctness matrix

The independent correctness test uses the 4 x 4 matrix
defined in Section 13, equation (14), of the P3 manuscript.

Its dimensions and sparse representation are:

| Property | Value |
|---|---:|
| Rows | 4 |
| Columns | 4 |
| NNZ | 7 |
| CSR values | (4, 2, 3, 1, 5, 2, 6) |
| CSR column indices | (0, 3, 1, 0, 2, 2, 3) |
| CSR row pointers | (0, 2, 3, 5, 7) |

The independent dense oracle test explicitly selects:

x = (1, 2, 3, 4)^T

and verifies:

y = A*x = (12, 6, 16, 30)^T

The manuscript defines x symbolically; the vector above is
the explicit test input, not a claim that this vector is
specified by the manuscript.

Test:
`P3/tests/CSRvsDenseOracleTest.java`

### 2.2 Large-scale performance benchmark matrix

`BenchmarkRunner.createBenchmarkMatrix(int n)` generates a
deterministic synthetic sparse matrix.

For each row i:

- A[i,i] = 1.0
- A[i,i+1] = 0.5, when i < N-1
- A[N-1,0] = 0.5, for the final row

The generated matrix has:

- N rows;
- N columns;
- NNZ = 2N;
- two stored entries per row.

The benchmark input vector is:

x[i] = 1.0

The expected output is:

y[i] = 1.5

This synthetic matrix is used for large-scale performance
measurement. It must not be described as the 4 x 4 manuscript
matrix from equation (14).

## 4. Measurement methodology

The benchmark performs the following operations:

1. Constructs the synthetic CSR matrix.
2. Constructs the input and output vectors.
3. Creates one ForkJoinPool.
4. Executes sequential warm-up iterations.
5. Executes parallel warm-up iterations.
6. Measures sequential CSR multiplication.
7. Measures parallel CSR multiplication using the same pool.
8. Computes average execution times.
9. Computes speedup and throughput.
10. Checks numerical consistency.
11. Persists the result in CSV format.

The ForkJoinPool is created before the measured parallel
iterations and reused. Pool construction and shutdown are
therefore outside the measured SpMV calls.

The reported setup time is not included in the sequential
or parallel average execution times.

## 6. Performance metrics

Let:

- T_seq be the measured average sequential execution time;
- T_par be the measured average parallel execution time.

Speedup is:

S = T_seq / T_par

Execution-time reduction is:

R = 1 - (T_par / T_seq)

The percentage reduction is:

R_percent = 100 * R

The reduction is not clamped to zero. If parallel execution
is slower than sequential execution, R is negative and this
must be reported as a slowdown.

The speedup and reduction must be calculated from the same
measured average times.

## 7. Numerical validation

The benchmark checks:

- sequential output against the expected value 1.5;
- parallel output against the expected value 1.5;
- maximum absolute difference between sequential and parallel
  outputs.

Acceptance tolerance:

epsilon = 1.0e-12

All three numerical checks must pass.

A performance result with failed numerical validation is
invalid and must not be used to support a speedup claim.

## 8. Raw data and provenance

The benchmark writer appends results to:

`P3/benchmarks/benchmark_results.csv`

This relative path is obtained when the benchmark is executed
with `P3` as the working directory.

The raw execution log must be preserved separately under:

`P3/results/raw/`

The exact command, environment information, and SHA-256
digests are documented in:

- `P3/results/Reproducibility.md`
